# Rosetta 独立标注工具

[English](README.md) | **简体中文** | [Deutsch](README.de-DE.md) | [日本語](README.ja-JP.md)

界面默认使用英语，可随时切换中文、德语和日语。切换语言会保留未保存的标注和自定义标签。

在浏览器里导入图片、点云、音视频和文本，配置标注项，管理任务，再把已保存的结果导出为 JSON。

![图片标注工作台](docs/images/05-editor-zh.jpg)

任务和本地文件保存在当前浏览器中。标注编辑器运行在独立的 iframe 服务里，地址由站点管理员配置。尚未连接该服务时，仍然可以导入文件、管理任务和导出已经保存的数据。

## 开始前

建议使用桌面版浏览器。原始文件请另外保留，完成一批数据后及时下载结果。清除本站的浏览器存储会删除本地任务、文件和已保存的连接；换一个浏览器打开，原来的任务也不会自动带过去。

界面默认显示英语。点击页面右上角的语言选择框，可以切换中文、德语和日语。标注页的语言选择框在左上角。浏览器会记住选择，内嵌编辑器也会跟着切换。

## 用内置图片跑一遍

1. 点击侧栏的 **开始标注**。
2. 在 **示例数据** 中选择 **图片目标标注**。道路图片随前端一起提供，不需要自己上传。
3. 点击 **查看数据与文件**，确认图片和文件引用。
4. **标注工具** 页签中已有矩形框、多边形和关键点三个默认标注项。第一次使用可以先保留它们。
5. 如果希望以后从任务列表继续打开这份示例，点击配置页底部的 **保存到任务**，再点击 **开始标注**。浏览器拦截新标签页时，允许本站弹出窗口后重试。

![选择示例或导入自己的数据](docs/images/01-start-zh.jpg)

**3D 点云标注** 和 **文本实体标注** 的操作入口相同。点云示例是一份道路场景，文本示例是一段出行记录。

## 配置标注项

配置页把工具和数据预览放在一起。需要确认当前文件时，展开 **查看数据与文件**。

![标注工具与图片预览](docs/images/04-tools-zh.jpg)

选择已有标注项，可以修改名称和可填写的字段。左侧的工具用于添加形状或属性。图片任务可以用矩形框标记车辆，用关键点标记位置。先配置本次任务需要的标注项即可。

已有任务的配置入口在 **任务管理 → 任务名称 → 配置标注工具**。修改会保存到该任务。切换界面语言会保留你自己填写的任务名称和标注项名称。

## 标一条数据并保存

进入标注页后，左侧是绘制工具，中间是数据，右侧是对象列表。

在图片示例里，选择 **2D 矩形框**，或者按 **2**，为车辆画框。用 **选中** 或 **1** 选择对象，再调整位置和边界。这个示例中的多边形和点分别对应 **3**、**4**。工具旁边显示的数字就是当前配置的快捷键。

编辑完成后，点击右下角的 **保存**。配置页的 **保存到任务** 用于创建可反复打开的任务，编辑器里的 **保存** 才会保存当前标注结果。

在编辑器中保存或导出，需要邮箱登录和有效 License。出现登录提示时：

1. 输入邮箱地址，点击 **获取验证码**。
2. 填写邮件中的六位验证码，完成登录。同一封邮件里也有 License。
3. 登录后会自动启用 License。如果没有启用，打开 **License** 入口，粘贴当前账号邮件中的证书。
4. 回到编辑器，再点一次 **保存**。返回任务列表后，可以通过 **上次保存** 确认结果已经写入。

浏览数据和配置任务可以不登录。邮箱与 License 服务由管理员单独部署。

## 导入自己的文件

临时处理少量文件时，可以在开始页点击 **选择文件** 或 **选择文件夹**。需要按任务跟踪一批数据时，进入 **任务管理 → 新建任务 / 批量创建**。

![创建前检查文件和任务清单](docs/images/02-import-zh.jpg)

在导入窗口中：

1. 选择 **本地文件**，再点击 **选择多个文件** 或 **选择父文件夹**。也可以直接把文件拖入窗口。
2. 独立文件使用默认的 **每个文件一个任务**。
3. 点云或图片连续帧放在同一个目录中，选择父文件夹后，切换为 **同目录连续帧**。不同子目录分别处理。
4. 检查任务名称，取消勾选不需要导入的文件。整批数据有共同要求时，可以填写标注说明。
5. 点击 **创建任务**。在任务列表中点击任务名称，即可查看详情、配置工具或进入标注。

本地导入支持以下扩展名：

| 数据类型   | 扩展名                                   |
| ---------- | ---------------------------------------- |
| 图片       | `.png`、`.jpg`、`.jpeg`、`.bmp`、`.webp` |
| 点云       | `.pcd`、`.ply`                           |
| 音频       | `.mp3`、`.wav`、`.ogg`、`.m4a`           |
| 视频       | `.mp4`、`.webm`、`.mov`                  |
| 文本和文档 | `.txt`、`.md`、`.html`、`.pdf`、`.docx`  |

文件扩展名受支持，也可能因为浏览器不支持其中的编码或文档内容而无法预览。导入窗口会列出被忽略的不支持文件、隐藏文件和空文件。本地导入不接受 SVG；内置图片示例使用的是随应用提供的 SVG 引用。

已有 `PublicAnnotationInput` JSON 或 `DataRecord` JSONL 时，使用 **JSON / JSONL** 页签。包含多条数据的输入会被拆成独立任务，已有的工具配置和标注结果会一同保留。

## 从任务列表继续工作

![导入文本和点云后的任务列表](docs/images/03-tasks-zh.jpg)

每一行对应一条数据，或一组连续帧。搜索框可以按任务名称、说明和来源查找；上方页签用于筛选进度。

- **待标注**：还没有确认提交的标注结果。
- **标注中**：已经开始处理，任务尚未完成。
- **已完成**：任务中的数据已有确认保存的结果。

点击任务名称进入详情。每行右侧的 **操作** 菜单可以修改名称和说明、导出已保存的数据，或删除任务。删除时会一并移除该任务在当前浏览器中的标注结果，需要保留的内容请先导出。

## 导出结果

导出前，先在编辑器中保存修改。任务导出读取的是最后一次写入该任务的结果。

打开 **导出设置**，选择方式并保存设置，再回到任务详情或任务的 **操作** 菜单中点击 **导出**。

![API 导出配置](docs/images/06-export-zh.jpg)

| 方式     | 需要填写的配置                                             | 导出结果                                                         |
| -------- | ---------------------------------------------------------- | ---------------------------------------------------------------- |
| 本地下载 | 不需要接收地址                                             | JSON 文件下载到当前设备。                                        |
| API      | 完整的 HTTP(S) 地址、POST 或 PUT，以及接口需要的鉴权请求头 | 发送 `PublicAnnotationInput` JSON，收到 2xx 响应后确认投递成功。 |
| 对象存储 | 已保存的 OSS、OBS 或 TOS 数据源，以及目录前缀              | 生成新文件名，把任务 JSON 上传到指定目录。                       |

API 地址支持 `{taskId}`，例如 `https://example.com/api/tasks/{taskId}/annotations`。接收方需要鉴权时，可以添加 `Authorization` 等请求头；接口还需要通过 CORS 允许本站来源。

导出的 JSON 包含文件引用、工具配置和标注结果，不包含原始图片、点云或音视频文件。请保留原文件。`local://` 引用指向导入文件的浏览器存储，把 JSON 发给别人，并不会把文件一同传过去。

## 使用对象存储里的数据

进入 **数据源 → 新建数据源**。

![新增对象存储连接](docs/images/07-storage-zh.jpg)

选择 OSS、OBS 或 TOS，填写 Bucket、Region 和访问凭证。**起始目录** 用于限定后续浏览的目录范围；可以使用服务商默认地域地址时，**Endpoint** 留空即可。临时凭证还需要 Security Token。

先点 **测试连接**，再点 **保存数据源**。回到创建任务窗口，选择 **对象存储**，选中数据源和目录，点击 **读取目录生成清单**。检查清单后再创建任务。

凭证需要目录列举和文件读取权限。Bucket 的 CORS 需要允许工作区和标注页来源的 GET、HEAD 请求。向 Bucket 导出时，还需要目标目录的 PutObject 权限，以及工作区来源的 PUT 请求权限。连接凭证保存在当前浏览器中，不会写入任务导出文件。

## 在本机运行前端

安装 Node.js 22.13 及以上的 22.x 版本，或 Node.js 24 及以上版本。

先安装 [pnpm 12.21.0](https://pnpm.io/installation)。`package.json` 固定了包管理器版本，依赖版本由 `pnpm-lock.yaml` 记录。

```sh
git clone https://github.com/stardustai/rosetta.git
cd rosetta
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm run dev
```

打开 [http://127.0.0.1:4174](http://127.0.0.1:4174)。已有标注服务时，在 `.env.local` 中设置地址：

```dotenv
VITE_ANNOTATION_URL=https://annotation.example.com/
```

修改环境文件后，需要重启开发服务。本地开发默认连接 `http://127.0.0.1:4175/`，该端口上的标注服务需要单独安装和启动。

## 发布到 GitHub Pages

[Pages 工作流](.github/workflows/pages.yml) 会检查类型，运行单元测试和 iframe 集成测试，构建前端，再发布成功推送到 `main` 的版本。Pull Request 只运行检查，不发布；也可以在 Actions 页面手动执行。

1. 在仓库 **Settings → Pages** 中，把构建来源设为 **GitHub Actions**。这一步需要仓库所有者或有 Pages 管理权限的人操作一次。
2. 将改动推送到 `main`。
3. 标注服务部署好后，在仓库的 **Actions variables** 中添加 `VITE_ANNOTATION_URL`，填写公开的 HTTPS 地址，再运行一次工作流。
4. 把 Pages 站点的 Origin 加入标注服务的 `VITE_HOST_ORIGINS`。Origin 不包含仓库路径。

前端可以先发布。没有填写标注服务地址时，编辑器位置会显示连接提示。API 和标注服务单独部署；iframe 中的邮箱登录还需要域名和 Cookie 设置满足 API 的 SameSite 要求。

工作流会处理 `/仓库名/` 路径，以及直接打开任务链接的情况。部署到其他静态服务器时，可以通过 `VITE_BASE_PATH` 设置路径前缀，并让应用路由回退到 `index.html`。

## 常见问题

| 遇到的情况               | 检查方法                                                         |
| ------------------------ | ---------------------------------------------------------------- |
| 显示“尚未连接标注服务”   | 部署标注服务后，设置 `VITE_ANNOTATION_URL` 并重新构建。          |
| 编辑器内显示连接错误     | 检查服务地址、HTTPS，以及标注服务允许的宿主来源。                |
| 点击开始标注没有新页面   | 允许本站弹出窗口后重试。                                         |
| 提示本地文件不存在       | 在原来的浏览器和站点中重新导入文件，并检查是否清理过浏览器数据。 |
| 导入后的清单为空         | 检查扩展名是否受支持，文件是否为空。                             |
| 对象存储访问被拒绝       | 检查 Bucket、Region、凭证有效期、目录权限和 CORS。               |
| 导出结果里没有刚才的修改 | 先在编辑器中保存，再导出任务。                                   |
| iframe 中的邮箱登录失败  | 请管理员检查 API、SMTP、允许的来源和浏览器 Cookie 策略。         |

## 开发检查

```sh
pnpm run typecheck
pnpm test
pnpm run test:render
pnpm run build
```

构建产物在 `dist/`。本地开发服务运行时，可以用 `pnpm run test:server` 检查页面入口和示例文件。

界面翻译使用 `src/messages.ts` 中的英文原文作为 key。iframe 宿主和带版本的数据定义在 [`src/annotation`](src/annotation/)。本地和生产构建都使用仓库内已提交的协议和数据定义。语言切换及如何从 `annotation-api` 同步更新见 [iframe 接入说明](docs/iframe-integration.md)。

OBS 和 TOS SDK 通过`pnpm-workspace.yaml` 中的定向 pnpm overrides 使用 axios 0.35.0。TOS 仍引用已删除的 `createError` 工厂，`vite.config.ts` 中的别名用公开的 `AxiosError` 类型补齐了这个接口。存储传输测试会运行两家真实的浏览器 SDK，通过本机 HTTP 服务检查签名请求、分页、JSON 上传和权限错误。TOS 移除旧引用前，更新 axios 时需要保留这个别名。

开发依赖和业务代码边界见[代码组织说明](docs/architecture.zh-CN.md)。
